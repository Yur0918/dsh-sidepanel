DSH 吸顶消息折叠失效 · 排查报告

对象：dsh-sidepanel 1.3.0–1.3.2 的「吸顶自动折叠 + 悬停手动折叠」· 样本会话：定时任务工作区「【每日定时播报 · DSH 插件市」· 环境DSH 0.1.1-rc.2 · 127.0.0.1:3080

问题：长消息折叠从未生效 根因已定位 已修复并实测验证（1.3.3） 29 项测试通过

结论（TL;DR）

根因：折叠逻辑量错了元素 —— flowItem 的第一个子元素是 display:contents 的插槽壳，scrollHeight 恒为 0

DSH 会话 UI 渲染每条消息时，会在 .flowItem 内先插一层插槽宿主 <div data-slot="conversation.chat.node" style="display:contents">。这个壳不生成 CSS 盒子，测高恒为 0。而折叠代码三处都用 item.firstElementChild 当内容元素：stickyCollapseFor({pinnedHeight: 0}) 恒判 none → 钉住长消息从不折叠、无「展开/收起」角标；0 > 100 恒假 → 悬停「折叠 ⌃」从不出现。配套 CSS 的 > div:first-child 也命中这层无盒壳，clip-path/背景全部落空。

该缺陷对所有会话、所有长消息生效，与具体会话无关——【每日定时播报 会话只是提示词最长（942px）、钉住后最显眼。吸顶 pin 本身（1.2.0 的 position:sticky）不受影响，所以看起来「钉住正常、折叠静默失效」。单元测试没拦住：纯函数测试只验证给定高度后的判定，DOM 测高这段不在覆盖内。

真实 DOM 结构（实测）

div.flowItem Md3f7G_flowItem —— 真实盒子 942px
└ 第一个子元素 = 折叠代码测高的对象
div[data-slot="conversation.chat.node"] style="display:contents" → scrollHeight = 0，无盒
└ 真实内容在壳里面
div.userRow 真实内容盒：942px（【每日定时播报 提示词）
└
div.userStack → div.bubble（播报正文 1368 字）

同一会话实测行高分布：播报提示词 942px（userRow）、上下文注入 chip 24px ×2、助手「Think + 回复」2037px（非 userRow，不在折叠设计范围）、统计行 28px。

排查过程

1
核对部署状态

插件已装（symlink → 仓库，1.3.2），线上 /plugins/dsh-sidepanel/client.js 与仓库文件 md5 一致，折叠代码已下发——排除「没部署/没加载」。

2
核对会话数据

解包 session.jsonl.zstd：播报长文是普通 user/message → 应渲染为 userRow，理论上应可折叠——排除「消息类型不匹配」。

3
真实页面 DOM 断言（ego-browser）

进入目标会话探测：吸顶 pin 生效（sticky:1）但 collapsed:0、无角标、foldable:0——折叠链路整体哑火。

4
锁定测量点

flowItem.firstElementChild = data-slot 壳（display:contents），scrollHeight=0；真实 userRow 是它的子节点（942px）。三处测高全部踩空。

修复方案（1.3.3）

不再假设「第一个子元素就是内容」

  • 新增 pickBoxedChild(item, displayOf, isOurs)：从 flowItem 向下穿透 display:contents 壳（跳过插件自己 appended 的角标/折叠条），找到第一个真实生成盒子的元素；displayOf/isOurs 可注入，纯逻辑可单测。
  • boxedChildOf(item) live 封装：顺手给真实盒打 .dsp-pin-box 类（幂等），CSS 不再依赖结构假设。
  • 三处测高/取文本（stickyCollapseFor 的 pinnedHeight、applyFoldPass 的 tall 判定、attachFoldBar 的摘要）全部改走 boxedChildOf。
  • CSS：> div:first-child 全部改为后代选择器 .dsp-pin-box（真实盒在壳内层，子选择器打不中）；折叠隐藏用 display:none!important（必须压过壳的内联 display:contents）。
  • 顺手修正 health 端点版本号（host 半 1.1.0 → 1.3.3，需重启 DSH 后生效，纯标识不影响功能）。

遗留与边界

  • 折叠功能按 1.3.0 设计只覆盖用户消息（userRow）。本会话里 2037px 的助手「Think + 回复」行不属于折叠范围（上下文注入行本身有原生收起 UI）。
  • 折叠/展开状态不持久化（1.3.0 既定设计），刷新后按当前滚动位置重新判定。
  • host 半（lib/index.js）的 VERSION 常量需 launchctl kickstart -k gui/$(id -u)/com.deepseek.dsh 重启后才显示 1.3.3；client 半修复即时生效，无需重启。
  • 浏览器里已打开的旧标签页需硬刷新一次才会加载修复后的 client。
